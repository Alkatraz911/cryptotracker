# CryptoTracker — fund-flow investigation

Расследование движения средств в браузере с личным кабинетом. Загружаете
**CSV/XLSX** экспорт с биржи (или добавляете кошельки/транзакции **по ссылке с
эксплорера**) → граф с правильным склеиванием связей (один адрес/UID/IP = один
узел) → сохраняете расследование в свой аккаунт. 6 сетей: **TRON, BSC, Arbitrum,
Base, Polygon, Ethereum**.

```
браузер (React)  ──/api──▶  Node + Fastify  ──▶  lowdb (JSON)        ← аккаунты, проекты
   граф в JS                     └──────────▶  Etherscan v2 / Tronscan ← подтяжка по ссылке
```

Без Docker, без Python, без нативных сборок — только Node.

## Запуск

Нужны два процесса.

**1) Сервер** (аккаунты + хранение + подтяжка с эксплореров):
```powershell
cd server
npm install
copy .env.example .env       # впишите ETHERSCAN_API_KEY, JWT_SECRET, DATABASE_URL
docker compose up -d         # Postgres (или укажите свой DATABASE_URL)
npm run dev                  # http://localhost:8787
```
> Сервер читает `.env` (dotenv). **Чтобы подтяжка транзакций работала, `ETHERSCAN_API_KEY`
> должен быть в `server/.env`** — без него EVM-запросы возвращают пусто (TRON работает без ключа).

### Хранилище
- Задан `DATABASE_URL` → **Postgres** (таблицы создаются автоматически при старте).
  `docker compose up -d` в папке `server/` поднимает локальный Postgres под дефолтный URL.
- `DATABASE_URL` пуст → fallback на `data.json` (lowdb). Слой изолирован в
  [server/src/storage/](server/src/storage/), переключение без правок роутов.

**2) Фронтенд:**
```powershell
cd frontend
npm install
npm run dev                  # http://localhost:5173  (проксирует /api → :8787)
```

Откройте http://localhost:5173 → **зарегистрируйтесь** → работайте.

## Возможности

- **Личный кабинет.** Регистрация/вход (email+пароль, пароли хэшируются bcrypt,
  сессия — JWT на 30 дней). Данные привязаны к аккаунту.
- **Память / проекты.** «Сохранить» пишет текущий граф в ваш аккаунт; список дел
  вверху — открыть / переименовать / удалить. Точка «•» = есть несохранённые
  изменения. Открытый проект **автосохраняется** в БД через ~2 с после правок.
- **Переживает обновление страницы.** Рабочий граф пишется в localStorage и
  восстанавливается после F5 — даже если вы ещё не нажали «Сохранить».
- **Загрузка CSV и XLSX**, несколько файлов сразу, со слиянием в один граф.
  Кодировка определяется автоматически (BOM → UTF-8 → иначе Windows-1251) и
  переключается вручную (UTF-8 / Windows-1251 / UTF-16 / 1252) — лечит кракозябры.
- **Добавление по ссылке.** Вставьте ссылку на транзакцию или адрес из любого из
  6 эксплореров. Если на сервере задан `ETHERSCAN_API_KEY` — from/to/сумма
  подтянутся автоматически; если нет — сеть и хэш/адрес распознаются из ссылки,
  остальное вводите руками. Всё доливается в текущий граф без дублей.
- **Догрузка истории кошелька.** Клик по кружку кошелька открывает диалог →
  «Загрузить транзакции»: выбираете сеть, **нативные и/или токен**-переводы и
  лимит, и они доливаются в граф (контрагенты становятся новыми узлами). EVM
  требует `ETHERSCAN_API_KEY`; TRON работает без ключа.
- **Диалоги вместо alert/confirm.** Все подтверждения и ввод имён — нормальные
  модальные окна (Esc / клик по фону закрывают).
- **Маркировка узлов.** В диалоге узла — раздел «Маркировка»: категория
  (Подозрительный / Жертва / Биржа / Миксер / Сервис / Вывод / Свой) + заметка.
  Помеченный узел перекрашивается в цвет метки, получает обводку и подпись на
  графе; метка сохраняется вместе с делом.
- **Защита от потери.** При переключении/создании дела с несохранёнными
  изменениями приложение предлагает сначала сохранить текущее.
- **Анализ.** Связанные аккаунты (общий IP=40, общий кошелёк=90), детали узла,
  кликабельные ссылки на эксплореры (двойной клик по узлу — открыть).

## Загрузка своих данных

Колонки определяются автоматически (имена не обязаны совпадать, есть ручной
маппинг). Понимает синонимы сетей: `TRX/TRC20→TRON`, `BNB/BEP20→BSC`,
`Arbitrum One→ARBITRUM`, `MATIC/POL→POLYGON`. Минимум для связей — адрес **или**
tx-колонка.

## Тесты

Браузерный E2E-смоук (Playwright) поднимает оба сервера, регистрируется,
грузит CSV, строит граф, открывает диалог узла и проверяет, что граф
переживает обновление страницы:
```powershell
cd frontend
npx playwright install chromium   # один раз
npm run e2e
```

## Замечания по безопасности

Аутентификация рабочая, но не закалена под продакшн: нет rate-limiting,
сброса пароля, подтверждения email. `JWT_SECRET` обязательно поменяйте в `.env`.
`data.json` — это вся БД (бэкапьте файл). Для серьёзного масштаба замените lowdb
на SQLite/Postgres — слой хранения изолирован в [server/src/db.js](server/src/db.js).

## Опционально: Neo4j-стек (для миллионов транзакций)

Остаётся в [backend/](backend/) как путь масштабирования с графовой БД. Для
описанного выше браузерного приложения **не нужен**.
